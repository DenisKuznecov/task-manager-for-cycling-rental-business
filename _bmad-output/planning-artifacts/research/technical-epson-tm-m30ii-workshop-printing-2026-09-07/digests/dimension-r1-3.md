## Synthesis and test requirements (inference/design proposals)

Prefer direct Chrome-to-printer LAN trial first; fallback QZ on mechanic Windows laptop. A cloud-polling local agent is an alternative custom architecture: agent initiates outbound cloud requests, then sends locally. This requires a maintained, available machine, durable queue and result reporting. It is not a native-printer capability assertion.

Represent attempts as queued/sending/confirmed/failed/unknown. Disable duplicate clicks while sending, retain stable logical job IDs, distinguish an intentional reprint. A timeout or lost acknowledgement must become unknown; offer operator inspection/reprint instead of automatic blind resend. Correlation IDs do not establish firmware deduplication. Test paper out, cover open, power loss, Wi-Fi interruption before/after submission, double-click, and long checklist.

Eight distinct sources used (cap reached). Follow-up should resolve exact-model SDP and newer ePOS status/timeout contract using existing source leads, avoiding product proliferation.
