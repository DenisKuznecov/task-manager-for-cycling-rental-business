Automating mechanics daily work

20 Aug 2026 · Den · Integration slice only. Checklist, M1/M2, add-ons, and pickup/return were not forged.

Outcome

The Booqable trigger model is clearer and partly locked. The wider MVP was not pressure-tested. Session ended because there was no time left, not because the idea was killed.

Locked

  • Assigner who sets the physical bike ID in Booqable also runs Sync. That creates first tasks and recovers silent orders.
  • Opening a task reconciles that order (siblings, add-ons, replacement).
  • Existing webhook, when it fires, uses the same reconciler. Belief: assignment of stock_items.id does not emit order.updated.
  • No automatic fetch on Today / Tomorrow / Next 7 days. Queue shows last successful sync time.
  • If the assigner skips Sync, a missing task is an accepted failure. No “assigned but unsynced” signal in MVP.

Rejected

  • Periodic polling / queue-open bulk sweep — extra hustle, tablet races, 429 risk; same job as the assigner’s Sync.
  • “API cannot see the new stock item until Sync” — false. Fetch can see it; the gap is the push event.

Still weak

  • Open-task sync does not refresh a task already on screen. Mid-work bike swap can stay invisible until leave/reopen. Unresolved when stopped.
  • Assignment webhook coverage is still a belief, not a tenant measurement.
  • Current order fetch is still include=customer,coupon,lines — no stock-item path in production yet.
  • Most of the product (gates, signatures, storage, add-on freeze after ready) was not examined.
